# AGENTS.md

## Scope

These instructions apply to the entire repository.

## Mission

Build a transparent, privacy-conscious job radar that discovers and
prioritizes realistic opportunities without inventing candidate experience
or automatically submitting applications.

## Privacy boundary

Public repository content may include:

- source code, templates, tests and documentation;
- public company and job information;
- generic or explicitly approved filtering preferences;
- sanitized example profiles using fictional data;
- generated public job-feed data.

Never commit:

- a real CV, phone number, email address or identity document;
- private candidate profiles or experience banks;
- application history, recruiter conversations or interview notes;
- tailored resumes, cover letters or private evaluation reports;
- credentials, tokens, cookies, API keys or local environment files;
- personal facts taken from chat memory unless the user has explicitly
  approved the exact wording for public release.

Public explanations must describe the job requirement, not expose a private
candidate fact. Prefer “This role requires 5 years of experience” over
“The candidate has no experience.”

## Truth and evidence

- Never invent or exaggerate experience, skills, ownership or results.
- Distinguish required qualifications from preferred qualifications.
- Unknown information is not evidence of rejection.
- Hard rejection requires an explicit, traceable blocker.
- AI-assisted and open-source-derived projects must be described honestly.
- Do not represent the candidate as an independent software developer unless
  verified evidence supports that claim.
- Preserve the source URL and evidence for every eligibility decision.

## Job evaluation

Use two stages:

1. Public eligibility screening based on job facts and approved public rules.
2. Private candidate-fit evaluation using private profile data outside this
   repository.

Use A/B/C/X outcomes:

- A: realistic match
- B: worthwhile stretch
- C: insufficient information; human review required
- X: confirmed hard blocker

Only X may be hidden automatically.

## Safety and automation

- Never auto-submit an application.
- Never send an email, message or form without explicit user approval.
- Respect job-site terms, rate limits and public-data boundaries.
- Validate external URLs and allow only HTTP/HTTPS links.
- Do not publish full copied job descriptions until the repository's content
  policy explicitly permits it.

## Repository workflow

- Do not work directly on `main`.
- Keep changes scoped and review the diff before committing.
- Do not manually edit generated files when a source file or generator exists.
- `docs/index.html` is generated from `template.html`.
- `data/jobs.json` and `docs/jobs.js` are generated by `radar.py`.
- Preserve unrelated user changes.
- Use clear, factual commit messages.

## Verification

For relevant changes, run at minimum:

```bash
python -m py_compile radar.py
python -c "import json; json.load(open('companies.json', encoding='utf-8'))"
```

When tests are added, also run:

```bash
python -m unittest discover -s tests
```

Report what was tested and any verification that could not be completed.
